# 2026-08-17 每日笔记

## 新修复：get_vdi_strategy 不混用教室策略 ID

### 问题

`get_vdi_strategy`（`space/strategygroup/vdi/list`）的 fallback 逻辑检查了 `strategyId` 字段，误匹配了 `createStrategy`（教室策略）产出的 `classroomStrategyId`，导致 VDI 课程策略使用了错误的教室策略 ID `11c561b2...`。

**旧逻辑问题：**
```python
for var in ("vdiStrategyId", "deskStrategyId", "strategyId", "id"):
    # "strategyId" 匹配了 createStrategy 的 classroomStrategyId
    # 但 classroomStrategyId 的值是教室策略 UUID，不是课程策略 UUID
```

### 修复

去掉 `strategyId` 关键词，只检查课程策略专用字段：
- `vdiStrategyId` — VDI 课程策略
- `tciStrategyId` — TCI 课程策略  
- `deskStrategyId` — 桌面策略
- `id` — 通用（从其他课程策略步骤产出匹配）

`classroomStrategyId`（教室策略）不在匹配列表中，不会被误用。

同时 `strategy_id_arr` 已清空为空，`get_vdi_strategy` 会正常调 API 查询。
